# 模块化的应用

小学六年级互动课件。一个 Go 服务同时提供学生端 `/`、教师端 `/teacher` 和 API。Node 构建原生 HTML、CSS、ES5 JavaScript；全部器材图为本地 SVG，不加载外站字体、图片或脚本。

## 上课流程

1. 打开 `https://你的域名/teacher`，用教师口令登录并创建课堂。本地默认口令为 `2026`。新课的六个活动全部锁定；同时只有一堂课开放，确认开启下一课才会归档原课堂。
2. 只发学生首页 `https://你的域名/`。学生打开即进入当前课堂，自动获得「学生01」到「学生50」的号码，不填姓名或课堂码。同一浏览器保留站点数据时重复打开不会再占座；隐私窗口、换设备或清除站点数据可能占用新座位。第 51 个浏览器会等座，不挤掉已入场学生；下一堂课重新编号。
3. 逐个开放或关闭活动。学生端前台约 3–4 秒同步；服务端立即拒绝未开放活动的读取和提交。换课后，学生首页会自动跟随新课堂，旧课堂记录仍可查看和导出。
4. 右下角「投屏展示」进入第 2 页，50 张座位卡显示入场情况、当前活动及进度。点击已入场的学生卡才加载其操作画面，关闭画面即停止同步。投屏是只读的网页状态复现，不是屏幕录制：不包含桌面、摄像头及鼠标轨迹，只同步课件内的操作和文本。未提交的实时状态只留在内存；服务重启或更换课堂后不提供历史回放。请提醒学生不要在自由文本中填写个人信息。
5. 需要清掉试课数据时，在当前课堂控制页先「导出 CSV」，再点「清除学生数据」并确认。此操作清除本堂课的座位、提交和实时进度，不改活动开放状态或历史课堂。仍打开学生页的浏览器会自动重新加入并领取座位；若希望保持空座，请先关闭学生页。

| 活动 | 学生操作 | 教师收到 |
| --- | --- | --- |
| 1 探解无人机模块 | 把六个模块装进对应机身凹槽，观察螺旋桨加速、起飞和降落 | 已装模块、联动完成标记 |
| 2 分析身边的模块 | 从五种设备中选一个，阅读整机功能，挑选自己认为设备包含的模块 | 设备与实际选择 |
| 3 探寻模块化优势 | 思考无人机维修、批量生产和摄像头升级，挑选自己认同的优势 | 实际选择 |
| 4 我来模块化实践 | 编辑五段独立积木，选中想封装的行，接好五处调用后对比运行 | 五段独立设置、选入模块的积木及设置、调用位置和观察结果 |
| 5 我是模块组装师 | 安装九个部件与线缆，接好显卡、鼠标、SATA 数据线、HDMI 线等后开机 | 部件与安装位置 |
| 6 无人机改造畅想 | 点击模块装上通用挂载口，观察同一架无人机换装后如何完成不同任务 | 已体验的模块及用途；投屏同步当前换装及演示 |

第 1–5 项支持拖拽，也可先点选卡片或部件，再点目标位置。第 2、3 项的空槽接收清单内任意未放入的卡片，不判正误，点已填好的槽可以移除；放入至少一张卡片即可提交。第 2 项换设备时会保留当前页面内的尝试，提交时只记录当前设备。无人机和电脑装配时进入正确槽位会先亮光环，错位松手会复位；装好会有动作和说明气泡。视频、实体硬件演示与奖品留在教案的线下流程。

彩灯编程包含起飞前、航拍中、左转、右转和降落后。先改一段独立积木，比较表里只有那一段变化。在同一事件勾选想复用的积木，再点工作区顶部唯一的「封装」；只有选中的行收进模块盒，模块调用插在第一个选中的位置，没选的行仍在每段中单独执行和编辑。点开模块盒可修改选中的共用积木，接入五个事件后改一次就能更新五处。两种写法都能运行，对照预览中的转向、灯色和执行高亮。收纳动画不依赖 CSS 关键帧；开启减少动态效果时以短淡入淡出为主，旧版三事件记录可继续查看，补接左右转后可更新。

无人机改装台提供高空洗窗、高山拾垃圾、彩灯表演、运送茶叶、农田喷洒、远程喊话、投放食物、夜间搜救和夜间照明。一次挂载一个模块，机身不做起降演示；点同一模块或「再演示」可重播其动作，换模块会保留已体验进度。至少体验一个模块即可提交，重新打开时恢复最近一次提交的挂载。

旧版的「生活搜寻」「小组研究」「电脑组装」和「校园安全卫士」记录保留原活动名称供查看和导出，不会算作当前课堂的新活动已完成。同一学生重新提交会更新该活动位的记录；如需单独留底，可先导出旧记录。

学生端以 **Chromium 49 / iOS Safari 12** 为兼容设计目标。试飞的起降和桨叶转动不依赖 CSS 关键帧。开启系统「减少动态效果」时，试飞仍会缓慢起降、转桨，不摇摆、不闪灯；装配和回弹也会减少动作。可点页头「播放完整动画」仅在此浏览器恢复完整效果。请在上课前用实际机房电脑和平板走一遍。

## 1Panel 部署

向 GitHub 仓库的 `main` 分支推送代码后，Actions 会在 x64 运行器上原生构建并发布 `ghcr.io/alumos/modulelab-classroom` 的 `linux/amd64` 镜像，不使用 QEMU。`latest` 指向最近成功发布的版本，`sha-<提交哈希>` 可用于锁定版本。先等待 Actions 显示成功，再部署。

1. 首次发布时，GHCR 包和 GitHub 仓库的可见性独立。公开 GHCR 包后，1Panel 可以匿名拉取，不需要 GitHub 账号或令牌。如果包还是私有，仓库管理员需先在包的设置中设为公开，或在 VPS 上配置只读拉取凭据。
2. 在 1Panel 新建编排，将 [`compose.1panel.yaml`](compose.1panel.yaml) 完整粘贴到 Compose 内容，再启动。教师口令直接写在编排内，示例值为 `"2026"`，不需要额外的 `.env`。这是公开的弱口令：若保留它，请通过可信网络或反代访问控制限制 `/teacher` 和 `/api/teacher/*`，学生首页不受限；开放教师端到公网时请改用 16–256 字节随机口令，不要把真实口令提交到仓库。
3. 用 1Panel 的网站反向代理将 HTTPS 域名转发到 `http://127.0.0.1:18326`，前提是反代运行在宿主机网络；如果反代运行在独立容器网络，改用同一 Docker 网络下的服务名和容器端口 `8080`。学生打开域名根路径，教师打开同一域名的 `/teacher`。如果启用 CDN，按下面的缓存规则配置。
4. 更新时在同一个编排里拉取新镜像并重建；命令行等效操作是 `docker compose pull && docker compose up -d`。保留编排名称和 `classroom_data` 卷，避免课件启动后读到空卷。师生页面页脚均有备案号链接。

如果不用面板的镜像仓库配置，可在 VPS 上执行 `docker login ghcr.io -u 你的GitHub账号`，在密码提示中输入 PAT；不要把凭据放进命令行参数。若国内 VPS 无法访问 GHCR，先确认该服务器的合法拉取渠道，或把镜像按相同架构同步到自己的镜像仓库，再替换 Compose 的 `image` 地址。

## VPS 源码构建

需已有 Docker Engine 和 Docker Compose V2。将项目文件上传到 VPS，在项目目录创建 `.env`（仅首次，已有配置不覆盖）。

```sh
umask 077
( set -C; {
  printf 'TEACHER_PASSWORD='
  openssl rand -hex 24
  printf 'COOKIE_SECURE=true\nBIND_IP=127.0.0.1\nWEB_PORT=18326\n'
} > .env )
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:18326/healthz
```

- **口令**：`2026` 是公开的本地试玩默认值，**不要用于公网**。上面的部署命令会生成随机口令。使用 HTTPS，从受信任的编辑器读取 `.env`，不要上传到公共仓库。自定义口令为 16–256 字节；修改后执行 `docker compose up -d`。公网部署推荐再限制教师页面和 `/api/teacher/*` 的访问；不要限制学生页面。
- **域名 / CDN**：建议只对外开放已有的 HTTPS 反代，把公网域名整站转发到 `http://127.0.0.1:18326`。若 CDN 使用 HTTPS 回源，请给反代配置受信任证书，不要直接将明文高位端口暴露公网。按 CDN 厂商的备案、区域和回源要求配置。
- **缓存**：CDN 必须绕过 `/api/*`，保留查询字符串、HTTP 方法、`Cookie` 与 `Set-Cookie`；`/`、`/teacher` 不强制缓存，静态 `/app.js`、`/style.css`、`/art.svg` 可依源站缓存头短期缓存。更新后可刷新这三个静态资源的 CDN 缓存。不开启会拦截共享机房请求的统一低频限速或人机验证，应在实际机房试课。
- **纯 HTTP 联调**：仅在本地或受信任的测试网络用 `COOKIE_SECURE=false`，上线使用 `true`。VPS 默认端口 `18326` 可由 `WEB_PORT` 修改；学生链接应使用最终域名，由教师从最终域名登录后复制。
- **数据**：每堂课独立 JSON，`active` 记录当前课堂，一起保存在 `classroom_data` 卷。停服备份整个命名卷会保留课堂、提交和座位。不要用 `docker compose down -v` 做例行重启。项目是单实例设计，每堂课最多 50 个座位，同实例最多保留 100 堂课。旧版升级后，已有课堂中的旧昵称会保留在记录里；新建一堂课即可启用完整的自动编号。
- **课后清理**：没有自动删除学生记录。按学校规定保留必要数据；如需删除已归档的课堂，部署人员可在停服并备份后删除卷内对应文件。不要删除 `active` 所引用的课堂。

## 开发验证

镜像构建会运行 `npm run build`、Go 测试与 Go 编译。没有 Docker 时，可使用已安装的 Node 和 Go（Go 1.23 以上）：

```sh
npm run check
npm run build
go test ./...
go vet ./...
go build -o ./modulelab .
```

本机试课可直接运行编译出的程序，设置 `COOKIE_SECURE=false HOST=127.0.0.1 PORT=18326`。未设置 `TEACHER_PASSWORD` 时口令为 `2026`。数据路径用 `DATA_DIR` 指定，默认 `./data`。座位识别使用随机浏览器令牌，提交内容不包含 IP、用户代理或设备指纹；反代或 CDN 的访问日志按学校要求另行设置。

投屏页用一个批量请求更新全部座位卡，摘要不含文本或操作草稿；只轮询被选学生的完整快照。学生仅在操作状态变化时合并上传小型 JSON，教师端收到未变更响应不重绘页面；这些操作快照不触发磁盘写入。测试覆盖 50 个 HTTP 请求同时抢座、课堂归档、未开放活动拦截及投屏读取权限；VPS 的实际延迟取决于机房网络与 CDN 回源。
